# 句式骨架与措辞库

这些骨架用于组织真实信息，不是可直接拼接的“万能段落”。每段最多选用一至两个骨架，随后按技术关系改写。相邻段不要连续使用同一句式。所有 `【】` 必须替换或删除。

## 1. 工程背景与问题

- 【生产/检测场景】中，【对象】的【工艺或性能特征】直接影响【产品质量/设备状态】。
- 现有【设备/方法】在【具体工况】下存在【可观察问题】，主要表现为【现象或数据】。
- 当【工况变化】时，【原有环节】难以满足【具体指标】，因此需要对【对象】进行【设计/改造】。
- 与【另一工况】相比，【目标工况】对【指标】提出了更高要求，其难点在于【技术矛盾】。
- 本设计着重解决【具体问题】，设计边界为【保留结构/接口/成本/安全约束】。

**不宜写**：“随着科技飞速发展，智能化已经深入人心，本课题具有十分重要的意义。”

## 2. 研究现状与文献综合

- 【作者/机构】针对【对象】采用【方法】，完成了【实现内容】，在【条件】下得到【结果/指标】【引用编号】。
- 该研究说明了【方法】在【场景】中的适用性，但其【条件/对象】与本课题存在【差异】。
- 与【方法A】侧重【方面】不同，【方法B】主要通过【途径】改善【指标】。
- 现有研究主要涉及【方向A】和【方向B】，其中【方向A】多用于【场景】，【方向B】则侧重【问题】。
- 已有成果为【环节】提供了方法基础，但在【具体工况】下，【变量/约束】之间的关系仍需进一步分析。
- 综合上述研究，本课题将【已有方法】用于【具体对象】，重点处理【尚未解决的工程问题】。

**避免**：每篇文献末尾都机械补一句“为本文提供了参考”；没有检索依据就写“国内外尚无研究”。

## 3. 研究内容与技术路线

- 围绕【总目标】，主要完成【工作A】、【工作B】和【工作C】。
- 首先依据【工艺/任务】确定【指标与接口】，随后完成【方案与实现】，最后通过【测试】检验【指标】。
- 研究内容中的【工作A】形成【输出】，并作为【工作B】的输入。
- 技术路线中的参数修正体现在：根据【测试结果】调整【参数/结构/逻辑】，再进行【复测】。

## 4. 功能需求与性能指标

- 根据【工艺流程/现场操作】，系统需具备【功能A】、【功能B】和【安全功能】。
- 自动模式用于【连续任务】，手动模式用于【调试/校准/故障处理】，两种模式通过【条件】切换。
- 【指标】以【测试方法】评价，其设计阈值为【真实数值】。
- 在保留【原有结构/接口】的前提下，新增【模块】，以实现【功能】。
- 【需求】对应【模块或参数】，其依据为【任务书/计算/现场/手册】。

**避免**：“系统精度非常高、响应非常快、可靠性很强。”

## 6. 硬件选型

- 在【相同工况与评价口径】下，【型号A】与【型号B】的差异主要体现在【指标】，因此选用【型号】。

## 15. 高风险措辞的替换方向

| 高风险表达 | 修改方向 |
|---|---|
| 显著提高、明显改善 | 给差值、比例、样本与工况；没有数据则改为“旨在改善” |
| 稳定可靠 | 写连续运行条件、故障记录、信号波动或具体联锁 |
| 精准控制 | 写控制对象、反馈量、误差指标和阈值 |
| 完全满足 | 写“在【条件】下满足【指标】” |
| 具有较高性价比 | 写同口径成本构成；无成本数据则删除 |
| 进行数据分析工作 | 分析数据，并写明分析内容 |
| 开展系统验证操作 | 验证系统，并写明方法和判据 |
| 这套系统用起来很方便 | 说明哪些操作步骤减少或界面功能如何实现 |
| 为后续奠定坚实基础 | 直接说明为下一模块提供何种参数、接口或结构 |
| 不仅……而且…… | 若只是并列，直接分句；若确为递进，保留一次即可 |
